# 匹配分打分逻辑（核心）

本 skill **不是**黑盒乱打分。默认流程：

1. **抽取并核对 JD 硬性要求**（防误判，优先于「技能看起来很像」）
2. **画像硬过滤**（城市 / avoid / must_have）
3. 按维度加权填打分卡 → 原始分 0–100
4. **硬性要求未过 → 强制降级封顶**（即使技能维很高也不能给 A）
5. 映射 **A / B / C** + 星级 + 推荐/风险文案
6. packet 存入 `applications/packets/{A|B|C}/`

权重见 [`config.example.yaml`](../config.example.yaml)。

---

## 等级（对外主结论）

| 等级 | 分数 | 含义 | 默认投递策略 | 目录 |
|------|------|------|--------------|------|
| **A** | 90–100 | 强匹配 | **建议优先 / 立即投递**；简历一般不用改 | `packets/A/` |
| **B** | 60–89 | 有机会 | 可投；**先按「简历修改建议」包装表述**（60–80 更要包装；81–89 机会较大） | `packets/B/` |
| **C** | &lt;60 | 不推荐 | **默认不进一键投递**；写清🚫原因；仅当你强制时才投 | `packets/C/` |

> 说明：口语里的「B级 80–60」= B 档里更需要包装的区间；本规则把 **60–89 都归 B**，避免 81–89 空档。

### 星级

| 分数 | 星级 |
|------|------|
| 90–100 | ★★★★★ |
| 80–89 | ★★★★☆ |
| 60–79 | ★★★☆☆ |
| 40–59 | ★★☆☆☆ |
| &lt;40 | ★☆☆☆☆ |

### 匹配结论文案

- A → `建议立即投递`
- B → `可以投递，建议先按「简历修改建议」包装表述`
- C → `🚫 不建议投递`

## 防误判：硬性要求（先于高分）

从 JD「任职要求 / 必备」中抽出硬性项，常见：

- 学历（硕士 / 硕士…）
- 工作年限（3年以上、5–10年…）
- 语言证书（英语六级、商务英语、日语N2…）
- 证书 / 执照
- 明确写「必须 / 限 / 仅」的技能或行业背景（如必须 B 端、必须 Google Ads）

对照简历后标记 `pass` / `fail`。

### 降级封顶（强制）

| 情况 | 处理 |
|------|------|
| 任 1 项硬性未过 | `score = min(score, 79)` → **最高 B**，禁止 A |
| 任 2 项及以上硬性未过 | `score = min(score, 59)` → **强制 C** |
| 学历/年限/语言等「筛选型」硬性未过 | 摘要卡必须写 `🚫 不建议投递原因` 或「投递风险」里标明会被刷 |
| 技能维很高但硬性未过 | **仍降级**（典型：技能匹配感 90，专科+英语弱+2年 vs 硕士六级+3年 → C 或顶多 B） |

示例文案：

```text
🚫 不建议投递原因：
- 要求：硕士 + 英语六级 + 3年以上
- 你的经历：专科、英语弱、约2年
- 技能表面匹配度：约90%（不足以抵消硬性门槛）
- 综合分：42% → C级
```

## 1. 画像硬过滤

| 规则 | 行为 |
|------|------|
| 城市完全不在目标且无远程 | 硬失败 → 倾向 C |
| 触发 `profile.avoid` | 硬失败 → C |
| `must_have` 明显不满足 | 硬失败或强制降级 |
| 薪资完全无交集 | 强扣分（默认 −15），不单独决定等级 |

---

## 2. 维度权重（默认合计 100）

| 维度 | 权重 | 要点 |
|------|------|------|
| role_domain | 25 | 岗位方向 |
| skills | 25 | 关键词命中（**不能**单独决定 A） |
| years | 15 | 年限 |
| education | 10 | 学历 |
| location | 10 | 地点 |
| salary | 10 | 薪资带 |
| prefs | 5 | 偏好 |

`raw_score` 算出后，再套用「硬性要求封顶」得到最终 `score`，再映射 A/B/C。

## 3. 打分卡 JSON

```json
{
  "company": "示例科技",
  "role": "新媒体运营",
  "hard_requirements": [
    {"name": "学历本科及以上", "jd": "本科", "you": "本科", "pass": true},
    {"name": "年限1-3年", "jd": "1-3年", "you": "约3年", "pass": true}
  ],
  "hard_fail_count": 0,
  "dimensions": {
    "role_domain": 23,
    "skills": 21,
    "years": 15,
    "education": 10,
    "location": 10,
    "salary": 8,
    "prefs": 4
  },
  "penalties": [],
  "raw_sum": 91,
  "score_before_cap": 91,
  "score": 91,
  "grade": "A",
  "stars": "★★★★★",
  "decision": "建议立即投递",
  "recommend_reasons": ["约3年内容运营经验匹配", "社媒/物料/复盘关键词命中"],
  "risks": ["薪资上限高于期望需面谈"],
  "reject_reasons": []
}
```

C 级时用 `reject_reasons`（🚫）；A/B 用 `recommend_reasons` + `risks`。

---

## 4. 投递优先级排序

批量展示与一键投递默认顺序：

1. `packets/A/` 按分从高到低  
2. `packets/B/` 按分从高到低  
3. `packets/C/` **默认不投**（除非 `强制投递` / 点名序号）

每日上限仍受 `max_apps_per_day` 约束。

---

## 5. 摘要卡必须出现的块

见 [templates/packet.txt](../templates/packet.txt) 顶部：

- 等级 + 分数 + 星级 + 匹配结论  
- **推荐原因 / 优势适配**（A/B）  
- **投递风险** 或 **🚫 不建议投递原因**（C 必填）  
- **硬性要求核对** 逐条通过/未通过  

---

## 6. 示例

### A 级 95（强匹配）

硬性全过 + 技能/方向高 → `A级 95分 ★★★★★` → `packets/A/` → 建议立即投递；简历修改建议写「无需改」。

### B 级 74（需包装）

方向对、有缺口但硬性基本过 → `B级 74分` → `packets/B/` → 推荐原因 + 风险；给出「内容发布 → 账号增长」类改写建议。

### C 级 42（硬性未过，防误判）

JD：硕士 + 六级 + 3年；你：专科 + 英语弱 + 2年；技能看起来 90：

1. `hard_fail_count = 3`  
2. 封顶 `score <= 59`  
3. `C级` + 🚫 不建议投递原因（要求 vs 你的经历 vs 匹配度%）  
4. 存入 `packets/C/`
